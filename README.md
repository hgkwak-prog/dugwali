# 두괄이 — 던지면 보고가 되는 업무 기록 에이전트

슬랙 봇 DM에 대충 적어 보내거나 통화가 끝나면, 두괄식·개조식 초안이 돌아오고 업무 로그가 자동으로 남습니다.

- **입구**: 슬랙 봇 DM(텍스트·음성 파일·전사문 파일), 안드로이드 통화 녹음 폴더
- **대시보드**: 이 PC의 브라우저에서 건·할 일·막힌 건을 한눈에 보는 화면
- **출구**: 슬랙 스레드 초안 + 버튼(슬랙 공유용 / 메일 양식 / 구두 보고 대본), 날짜별·건별 Markdown 업무 로그, 매일 17:30 미완료 리마인드
- **건 단위 관리**: 같은 일에 대한 통화·지시·후속 메모를 한 건으로 묶어 통합 정리
- **LLM**: 구독 계정으로 로그인한 Claude Code(기본) 또는 Claude API 키 중 선택. 기록 1건당 1회, 하루 상한 있음
- **음성**: 로컬 전사(기본, 음성 파일이 밖으로 나가지 않음) 또는 외부 전사 API 중 선택

## 1. 설치와 실행 (윈도우)

준비물: 파이썬 3.11 이상(설치할 때 "Add to PATH" 체크), 그리고 [Claude Code](https://claude.com/claude-code)를 설치해 구독 계정으로 한 번 로그인해 두기.

1. `run.bat`을 더블클릭합니다. 가상환경을 켤 필요가 없습니다. 처음에는 패키지를 설치하느라 몇 분 걸립니다.
2. 브라우저에 **첫 설정** 화면(`http://127.0.0.1:8765/setup`)이 열립니다. 화면의 안내대로 하면 됩니다.
   1. **슬랙 연결**: 슬랙 앱을 만들고(매니페스트를 붙여 넣으면 됨) 토큰 2개와 내 멤버 ID를 넣고 `확인하고 저장`. 실제로 슬랙에 확인한 뒤에만 저장하고, 통과하면 내 DM으로 확인 메시지가 옵니다. 2번 절에 같은 내용이 있습니다.
   2. **LLM 확인**: `연결 확인`을 누릅니다.
   3. **프로필**: 6가지를 물어 내 정리 기준을 만듭니다. 비워 둔 칸은 예시 값으로 채웁니다.
3. 슬랙에서 두괄이에게 DM으로 메모를 보내면 첫 초안이 옵니다.

- 실행할 때마다 패키지 목록이 바뀌었는지 보고, 바뀌었으면 다시 설치합니다. 이 PC 전사 패키지(용량 큼)는 전사 방식이 `이 PC`일 때만, Claude API 패키지는 LLM이 `API 키`일 때만 설치합니다.
- 오류로 멈추면 10초 뒤 자동으로 다시 켭니다. 끄려면 창을 닫으세요.
- 설정은 대시보드의 `설정`에서 바꿉니다. `.env`를 직접 열 필요가 없습니다. 다시 켜야 하는 설정은 그 화면의 `두괄이 다시 켜기`로 바로 다시 켭니다.
- 로그는 창과 `data\dugwali.log`에 함께 남습니다.

**윈도우 로그인 시 자동 시작**: `autostart-on.bat`을 한 번 실행하면 다음 로그인부터 최소화된 창으로 켜집니다. 해제는 `autostart-off.bat`입니다. 두괄이가 꺼져 있는 동안 생긴 통화 녹음은 자동으로 처리하지 않고, 다시 켰을 때 처리할지 묻습니다.

### 직접 실행 (명령줄)

`run.bat`이 만든 가상환경의 파이썬을 직접 부르면 활성화 없이 CLI를 쓸 수 있습니다. 아래 `python`은 모두 `.venv\Scripts\python.exe`로 바꿔 써도 됩니다.

Claude Code를 설치하고 구독 계정으로 한 번 로그인해 둔 뒤 점검합니다.

```bash
python -m dugwali.cli check
```

`{'ok': True}`가 나오면 LLM 연결은 끝입니다. 슬랙 없이 바로 써 볼 수 있습니다.

```bash
python -m dugwali.cli note "방금 김과장님 통화함. 견적서 금요일까지 다시 달라고 함"
```

정리에 실패하면 원문은 저장되고 기록 번호가 나옵니다. 실패한 것은 `attention`으로 보고 `retry 번호`로 다시 정리합니다.

```bash
python -m dugwali.cli attention
```

## 2. 슬랙 앱 만들기

첫 설정 화면에 같은 안내와 매니페스트가 있습니다. 토큰은 그 화면에 넣는 것이 편합니다(확인 후 `.env`에 저장). `.env`에 직접 적어도 됩니다.

1. https://api.slack.com/apps → Create New App → **From a manifest** → 아래 붙여넣기
2. Basic Information → App-Level Tokens → `connections:write` 범위로 생성 → `SLACK_APP_TOKEN` (xapp-)
3. Install App → 워크스페이스에 설치 → `SLACK_BOT_TOKEN` (xoxb-)
4. 내 프로필 → 더보기 → 멤버 ID 복사 → `OWNER_SLACK_USER_ID`

```yaml
display_information:
  name: 두괄이
features:
  app_home:
    messages_tab_enabled: true
    messages_tab_read_only_enabled: false
  bot_user:
    display_name: dugwali
    always_online: true
oauth_config:
  scopes:
    bot:
      - chat:write
      - im:history
      - im:read
      - im:write
      - files:read
      - reactions:write
settings:
  event_subscriptions:
    bot_events:
      - message.im
  interactivity:
    is_enabled: true
  socket_mode_enabled: true
```

실행: `run.bat` 더블클릭 (또는 `python -m dugwali.app`)

슬랙에서 두괄이 앱 → 메시지 탭에 아무렇게나 적어 보내면 됩니다. `도움말`, `건`, `할일`, `오늘`, `조치`, `프로필`, `대시보드`, `대시보드 로그아웃` 명령이 있습니다.

### 건으로 묶기

메모 하나는 기록 하나이고, 같은 일에 속한 기록을 묶은 것이 **건**입니다. 새 메모는 새 건으로 시작합니다.

- **합치기**: 진행 중인 건과 같은 일로 보이면 초안에 `↪ #3 …에 합치기` 버튼이 뜹니다. 자동으로 합치지는 않습니다. 제안이 없어도 `다른 건에 합치기` 메뉴에서 직접 고를 수 있습니다.
- **사후 보강**: 일이 끝난 뒤의 후속 내용도 새 메모로 던지고 같은 건에 합치면 됩니다. 종결한 건에 합치면 다시 열립니다. 한 기록의 내용만 고칠 때는 그 스레드에 답글을 답니다.
- **통합 정리**: `건` → `정리 보기`. 건에 속한 기록 전체를 최신 상태 기준으로 하나의 두괄식 정리로 만들고, 양식 3종도 그대로 쓸 수 있습니다. 합칠 때 기록마다 겹쳐 나온 할 일도 하나로 정리됩니다.
- **삭제·종결**: 초안의 `삭제`는 그 기록만, `건` 목록의 `삭제`는 건 전체를 휴지통으로 옮깁니다(30일 안에 대시보드에서 되살릴 수 있음). `종결`은 건을 목록과 마감 정리에서 숨기고 남은 할 일을 완료 처리합니다. 다시 열면 되돌아옵니다.

요약 승인 전의 통화 전사문은 건에 합쳐도 통합 정리(LLM 전송)에 포함되지 않습니다.

### 처리에 실패했을 때

어떤 건이 막혀도 조용히 사라지지 않습니다.

- **원문 먼저 저장**: 메모와 전사문은 받자마자 저장하고 그다음에 정리합니다. 정리(LLM)가 실패해도 원문은 남고, 그 자리에 `다시 시도` 버튼이 뜹니다.
- **통화 녹음**: 전사나 전송이 실패하면 DM으로 알리고 `다시 시도` 버튼을 냅니다. 이미 전사한 파일은 다시 전사하지 않습니다.
- **음성 메모**: 받아쓰기에 실패해도 기록이 남아 `다시 시도`할 수 있습니다.
- **`조치`**: 처리 실패, 아직 정리 안 된 기록(요약 버튼을 안 누른 통화 포함), 놓친 통화 녹음을 한 번에 보여줍니다. 마감 정리에도 건수가 나옵니다. AI의 판단이 아니라 DB와 녹음 폴더를 조회한 결과이고, "막힌 건이 없습니다"는 이 세 가지가 0건이라는 뜻입니다. 해야 할 업무는 `할일`에서 봅니다.
- **마감 정리**: 하루 한 번만 보냅니다(재시작해도 다시 보내지 않음). 전송에 실패하면 10분 간격으로 3번까지 다시 시도하고, 그래도 안 되면 `조치` 목록에 남깁니다.
- **마감 정리 순서**: 기한이 지났거나 오늘·내일까지인 내 할 일 → 조치 필요 → 오늘 다룬 건 → 복귀 지점 → 이전부터 열려 있는 건.

## 3. 통화 녹음 연결 (선택)

```bash
pip install -r requirements-stt.txt
```

1. 폰의 통화 녹음 폴더를 Syncthing(또는 FolderSync)으로 NAS 폴더에 동기화합니다.
2. 랩탑에서 그 NAS 폴더를 Tailscale로 붙여 드라이브로 연결하고 `.env`의 `CALL_DIR`에 적습니다.
3. 먼저 속도를 잽니다. 5분 통화가 10분 안에 끝나면 그대로 쓰고, 느리면 `WHISPER_MODEL=small`로 낮춥니다.

```bash
python -m dugwali.cli transcribe 녹음파일.m4a
```

- 앱을 켠 뒤에 생긴 녹음만 자동으로 처리합니다. 처음 설치하기 전의 파일은 건드리지 않고, 설치 뒤에 생겼는데 놓친 파일(꺼져 있었거나 늦게 동기화됨)은 `모두 처리` / `건너뛰기`를 묻습니다. 답하지 않으면 다음에 켤 때 다시 묻습니다.
- `SEND_CALLS_TO_LLM=false`(기본)면 전사문은 로컬에만 저장되고, 슬랙에 뜨는 **"요약하기"** 버튼을 눌러야 LLM으로 갑니다. 회사 승인이 나면 `true`로 바꾸세요.
- 화자 구분은 `pyannote.audio`와 `torch`를 설치하고 `HF_TOKEN`을 넣으면 켜집니다(Hugging Face에서 `pyannote/speaker-diarization-3.1` 약관 동의 필요). 없으면 화자 표기 없이 전사하고 LLM이 문맥으로 구분합니다.

## 4. 대시보드

두괄이를 켜면 같이 뜹니다. **두괄이가 켜져 있는 그 PC의 브라우저**에서 엽니다. 슬랙 DM에 `대시보드`를 보내면 주소를 알려 줍니다.

```
http://127.0.0.1:8765/
```

| 화면 | 보는 것 | 할 수 있는 것 |
|---|---|---|
| 건 | 진행 중인 건과 결론, 종결한 건 | 건을 열어 통합 정리·할 일·기록·원문 보기, 정리 내용 수정, 할 일·메모 더하기, 기록 옮기기·떼어내기, 종결·다시 열기, 삭제 |
| 할 일 | 기한이 지났거나 오늘·내일인 내 할 일 → 내 할 일 → 받을 일 | 완료, 되돌리기, 수정 |
| 조치 필요 | 처리 실패, 정리 안 된 기록, 놓친 통화 녹음, 아직 답하지 않은 질문 | 다시 시도, 넘기기, 정리하기 |
| 전사문 가져오기 | — | 다른 도구에서 전사한 내용을 붙여 넣어 기록으로 받기 |
| 프로필 | 프로필이 어떻게 읽혔는지, LLM에 함께 보내는 내용, 규칙 후보 | 처음이면 인터뷰로 만들기, 고치기, 규칙 후보를 정리 기준에 넣기 |
| 휴지통 | 지운 건·기록·할 일과 남은 기간 | 되살리기 |
| 설정 | 전사·LLM 방식, 하루 호출 상한, 마감 정리 시각, 통화 폴더 등 | 바꾸기(이 PC에서만). API 키는 화면에 다시 보여주지 않음 |

- **기본은 이 PC에서만 열립니다.** `127.0.0.1`에만 뜨고, 이 PC에서 열 때는 로그인이 없습니다. 다른 기기에서 열려면 아래 "다른 기기에서 열기"를 설정합니다.
- 화면을 여는 것만으로는 LLM을 부르지 않습니다. LLM으로 보내는 버튼에는 그렇게 적혀 있습니다.
- 대시보드에서 고치면 슬랙의 초안, 메일 양식, 업무 로그도 같은 내용으로 바뀝니다.

### 다른 기기에서 열기 (Tailscale + 슬랙 로그인)

두괄이는 사무실 PC에 켜 두고 집 PC나 폰에서 대시보드를 열 때 씁니다. 두괄이는 인터넷이나 사내망에 직접 노출되지 않습니다. **그 PC까지 닿는 길은 Tailscale**이 맡고, **누구인지는 슬랙**으로 확인합니다.

1. 두괄이가 도는 PC와 접속할 기기 모두 같은 Tailscale 계정으로 로그인합니다.
2. 두괄이가 도는 PC에서 한 번 실행합니다. 출력에 나오는 `https://….ts.net` 주소를 적어 둡니다.

```bash
tailscale serve --bg 8765
```

3. `.env`에 그 주소를 적고 두괄이를 다시 켭니다.

```
DASHBOARD_URL=https://내PC이름.tailXXXX.ts.net
```

4. 접속할 기기에서 Tailscale을 켜고 그 주소를 엽니다. 로그인 화면의 **슬랙으로 로그인 링크 받기**를 누르면 봇이 내 DM으로 **10분 안에 한 번만 쓸 수 있는 링크**를 보냅니다(슬랙 DM에 `대시보드`를 보내도 같습니다). 링크를 열어 `로그인`을 누르면 보려던 화면으로 가고, 그 브라우저는 30일 동안 다시 묻지 않습니다.

- 봇은 내 DM에만 링크를 보내므로, 슬랙에 나로 로그인한 사람만 대시보드에 들어올 수 있습니다.
- **로그아웃**: 대시보드의 `접속 관리`에서 브라우저별로 끊거나 모두 끊습니다. 슬랙에 `대시보드 로그아웃`을 보내도 모두 끊깁니다. 폰을 잃어버렸을 때 쓰세요.
- 공용 PC에서는 로그인하지 마세요.
- 폰의 슬랙 앱 안에서 링크가 열리면, 메뉴의 `브라우저에서 열기`로 연 뒤 로그인하세요. 앱 안 브라우저는 로그인을 기억하지 못할 수 있습니다.
- 로그인 화면에서 링크를 받는 것은 30초에 한 번, 10분에 5번까지입니다.
- 이 PC에서 직접 연 화면은 지금처럼 로그인 없이 열립니다.
- 두괄이를 다시 켜도 열려 있던 화면과 로그인은 그대로 동작합니다.

### 고친 값은 지켜집니다

- **직접 고침**: 대시보드에서 고친 항목(결론, 결정, 할 일의 기한 등)은 "직접 고침"으로 표시됩니다. 그 뒤 슬랙 답글이나 합치기로 다시 정리해도 **LLM이 그 값을 덮어쓰지 않습니다.** 표시는 수정 화면에서 지울 수 있습니다.
- **완료 추정**: 다시 정리했더니 LLM이 어떤 할 일을 더는 언급하지 않으면, 지우지 않고 "완료 추정"으로 표시합니다. `완료 맞음` / `아직 남음` 중 하나를 눌러야 정리됩니다.
- **휴지통**: 삭제는 휴지통으로 옮기는 것입니다(슬랙의 삭제 버튼도 같음). 30일 안에는 되살릴 수 있고, 그 뒤 완전히 지워집니다. 전사문 파일과 음성 파일은 지우지 않습니다.
- **종결**: 건을 종결하면 남은 할 일이 완료 처리되고, 다시 열면 그 할 일들이 되돌아옵니다.
- 사람이 고친 내용은 수정 이력으로 쌓입니다(나중에 프로필의 정리 기준으로 올리는 데 씁니다).
- 포트가 겹치면 `.env`의 `DASHBOARD_PORT`를 바꿉니다. `0`이면 띄우지 않습니다.
- 슬랙 없이 대시보드만 띄울 수도 있습니다: `python -m dugwali.cli dashboard`

### 다른 도구에서 전사한 결과 가져오기

로컬 전사가 느리거나 긴 녹음을 다른 전사 도구로 돌렸을 때 씁니다. 슬랙 DM에 `.txt` / `.vtt` / `.srt` 파일을 올리거나, 대시보드의 **전사문 가져오기**에 붙여 넣습니다. 자막 형식이면 번호와 시간은 알아서 빼고, 화자 표기는 살립니다. 통화 녹음과 같은 승인 게이트(`SEND_CALLS_TO_LLM`)를 따릅니다.

## 5. 내 스타일로 정리하기 (프로필)

무엇을 강조하고 어떤 말투와 양식으로 정리할지는 코드가 아니라 **프로필 파일**(`data\profile.md`)에 적습니다. 파일이 없으면 기본값으로 정리합니다.

**대시보드에서 만들기**: 프로필이 없으면 `프로필` 화면이 역할, 보고 대상, 업무 유형, 말투, 꼭 챙길 것, 용어를 묻고 만들어 줍니다. 업무 유형은 `기본`, `영업·사업개발 PM`, `개발자` 예시 중 고르고, 답한 칸만 바꿉니다. 만든 뒤에는 같은 화면에서 고칩니다(저장 전 내용은 `profile.md.bak`에 한 벌 남음).

명령줄로 예시에서 시작해도 됩니다.

```bash
python -m dugwali.cli profile --init sales-pm
```

저장하면 재시작 없이 다음 정리부터 반영됩니다.

**쓰면서 규칙 쌓기**: 대시보드에서 같은 항목(제목, 결론, 결정, 확인 필요, 배경, 할 일 문구)을 3번 고치면 `프로필` 탭에 "규칙으로 올릴까요?"가 뜹니다. 고친 사례를 보고 규칙을 직접 적거나, `LLM으로 초안 만들기`(1회 호출)로 초안을 받아 고친 뒤 `프로필에 넣기`를 누르면 `## 정리 기준`에 한 줄 더해집니다. 사람이 눌러야만 들어가고, `넘기기`를 누르면 그 뒤로 다시 3번 고칠 때까지 묻지 않습니다. 기한·담당자 수정은 사실을 고친 것이라 후보로 세지 않습니다.

| 절 | 쓰임 |
|---|---|
| `## 나`, `## 정리 기준`, `## 말투`, `## 용어` 등 | 그대로 LLM에 전달됩니다. 절 이름과 내용은 자유롭게 바꾸거나 더해도 됩니다 |
| `## 양식` | 두괄이가 직접 읽습니다. `슬랙 순서`, `메일 순서`, `메일 인사말`, `메일 맺음말` |

- 순서에 쓸 수 있는 항목은 `결정`, `할 일`, `확인 필요`, `배경`, `복귀 지점`입니다. 적지 않은 항목은 그 양식에서 빠집니다. 결론은 항상 맨 위에 옵니다.
- 메일 인사말의 `{대상}`은 공유 대상 이름으로 바뀝니다.
- 업무 로그(Markdown)는 기록이라 프로필과 무관하게 모든 항목을 남깁니다.
- **어떻게 읽혔는지 확인**: 슬랙 DM에 `프로필`, 또는 `python -m dugwali.cli profile`. 모르는 설정이나 오타는 ⚠️로 알려 줍니다.
- 프로필 내용은 LLM을 부를 때마다 함께 전송됩니다. 밖으로 나가면 안 되는 정보는 적지 마세요.
- 프로필로 바꿀 수 없는 것: 정리 결과의 항목 구성, "입력에 없는 사실을 지어내지 않는다", 연락처 마스킹, 전사문 승인 게이트. 이것들은 코드가 강제합니다.

## 6. 전사·LLM 방식 고르기

대시보드 `설정`(또는 `.env`)에서 바꿉니다. 기본값은 가장 보수적인 조합입니다(전사는 로컬, 전사문은 버튼을 눌러야 LLM으로 감).

| 설정 | 값 | 밖으로 나가는 것 |
|---|---|---|
| `STT_PROVIDER` | `local`(기본) | 없음 |
| | `api` | **음성 파일**이 `STT_API_BASE_URL`의 제공자로 감 |
| `LLM_PROVIDER` | `claude_code`(기본) | 마스킹한 **텍스트**가 구독 계정의 Claude로 감 |
| | `api` | 마스킹한 **텍스트**가 Claude API로 감 |
| `SEND_CALLS_TO_LLM` | `false`(기본) | 통화·음성 메모 전사문은 건마다 버튼을 눌러야 LLM으로 감 |
| | `true` | 전사문이 자동으로 LLM으로 감 |

- **외부 전사 API**: OpenAI 호환 형식(`POST {주소}/audio/transcriptions`)이면 연결됩니다. `STT_API_BASE_URL`, `STT_API_KEY`, `STT_API_MODEL`을 채웁니다. 파일 이름은 보내지 않습니다. 화자 구분은 하지 않고, 실패하면 `다시 시도`와 함께 `로컬 전사로 다시 시도` 버튼이 뜹니다(로컬 전사 패키지가 설치돼 있을 때).
- **Claude API**: `LLM_PROVIDER=api`, `LLM_API_KEY`를 채웁니다. 필요한 패키지는 `run.bat`이 다시 켤 때 설치합니다(명령줄이면 `pip install -r requirements-api.txt`). 기본 모델은 `claude-opus-5-5`이고, 비용을 줄이려면 `LLM_API_MODEL`을 `claude-sonnet-5-5`나 `claude-haiku-5-5`로 바꿉니다. 모델이 안전 분류로 처리를 거절하면 서버가 대체 모델로 이어 처리하도록 켜 두었습니다(`LLM_API_BASE_URL`을 쓰면 꺼짐).
- **하루 호출 상한**: `LLM_DAILY_LIMIT`(기본 200회). 닿으면 원문만 보관하고 `조치` 목록에 올립니다. 일시적인 LLM 오류는 한 번 자동으로 다시 시도합니다.
- **세션 기록**: Claude Code 방식은 호출 내용을 PC에 세션 기록으로 남기지 않는 옵션으로 호출합니다. 이 옵션이 없는 구버전이면 로그에 경고를 남기고 그대로 호출합니다.
- **음성 메모도 같은 게이트**: 슬랙에 올린 음성 파일의 전사문도 `SEND_CALLS_TO_LLM`을 따릅니다. 회사 승인이 있으면 `true`로 두세요.

## 7. 구조

| 파일 | 역할 |
|---|---|
| `dugwali/agent/llm.py` | LLM 호출(Claude Code / Claude API), 전송 전 마스킹. **다른 LLM을 붙일 때 여기만 수정** |
| `dugwali/profile.py` | 개인 프로필(`profile.md`) 읽기, 인터뷰로 만들기, 규칙 더하기 |
| `profiles/` | 직무별 프로필 예시 |
| `dugwali/agent/extract.py` | 프롬프트와 공통 스키마 추출 |
| `dugwali/agent/render.py` | 스키마 → 슬랙/메일/구두/Markdown 양식 (LLM 미사용) |
| `dugwali/pipeline.py` | 원문 저장 → 추출 → 로그 갱신, 건 병합·통합 정리·삭제 |
| `dugwali/ingest/slack.py` | 슬랙 봇 |
| `dugwali/ingest/watcher.py` | 통화 녹음 폴더 감시 |
| `dugwali/ingest/transcript.py` | 다른 도구에서 전사한 파일(.txt/.vtt/.srt) 읽기 |
| `dugwali/web.py` | 로컬 대시보드 |
| `dugwali/onboard.py` | 첫 설정: 슬랙 토큰·LLM 연결 확인, 슬랙 앱 매니페스트 |
| `dugwali/envfile.py` | 설정 화면에서 `.env` 고치기(주석과 순서 유지) |
| `dugwali/deps.py` | `run.bat`이 켤 때마다 설정에 맞는 패키지 설치 |
| `dugwali/stt/transcribe.py` | 전사 방식 고르기, 로컬 전사, 화자 구분 |
| `dugwali/stt/api.py` | 외부 전사 API 호출 |
| `dugwali/digest.py` | 일일 정리 |
| `dugwali/store.py` | SQLite (건·기록·할 일·처리 실패·앱 상태·수정 이력). 휴지통, 직접 고침 표시. 이전 버전 DB는 시작할 때 자동 이전 |
| `dugwali/views.py` | 보여줄 때 쓰는 정리 결과(지금의 할 일을 입힌 것) |
